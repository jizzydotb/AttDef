# Regression smoke tests

There is no automated Pawn runtime-test harness in this repository yet. Run these checks on a disposable server and a copy of `scriptfiles/AttDefDatabase.db`; never use the production database for failure-injection tests.

## Build checks

```powershell
sampctl build dev
sampctl build release
```

Both profiles must compile. Existing `Pawn.RakNet.inc` macro-redefinition warnings are unrelated to these checks.

## Startup and data loading

1. Start with the unmodified example database. Confirm the server loads its configuration, map packs, DMs, and commands.
2. Start from a database at schema version 2. Confirm migration 3 inserts AntiCBug and AntiSlideBug disabled, preserves existing config values, and allows the server to load all required options.
3. Start from a database at schema version 3. Confirm migration 4 adds `Players.TAssists` with a default of zero and preserves all existing player records and statistics.
4. On a database copy, remove a required `Configs.Option`, add a duplicate option, and add a distinct extra option in separate runs. Missing and duplicate required data must stop initialization with a clear error; the extra option and legacy `MainBackgroundColour`/`MainTextColour` rows must be ignored without preventing startup.
5. On a database copy, replace `Main Spawn`, `RoundHPAR`, `Maximum Packetloss`, or a boolean option with malformed values. Startup must reject the configuration before applying partial values.
6. Load each base pack and arena pack. Confirm IDs, names, spawns, and map counts are intact. Include arena records with the optional five-part CP spawn and DM records without a heading; missing DM headings should continue to use angle zero.
7. On a database copy, set an arena's minimum X or Y bound equal to or above its maximum, or move a normal arena bound outside -3000..3000. The arena pack must be rejected with an explicit error. Interior sentinel bounds must be accepted and normalized before camera/zone logic runs.
8. On a database copy, corrupt a spawn tuple or duplicate an ID in a pack. A failed pack load must report the problem and retain the prior in-memory pack and selected pack setting.
9. Remove all DM rows on a database copy. Startup should still work with an empty DM list.
10. Run `/base create`; the inserted row must use valid three-coordinate spawn tuples and load successfully. Attempt to delete the last base; the command must reject it without changing the pack.
11. Open the base-pack dialog, start a round from another player before selecting a pack, then select one. The response must refuse to change packs while the round is active.
12. While a player is restricted during round startup, try blacklisted commands both with and without parameters. Both forms must be denied unless the player is an admin.
13. Start `/ra` and confirm a restricted command is denied during the countdown, then use `/netcheckme` after players spawn; it must no longer report that the round is starting. Repeat with `/rb` and `/rava`. Verify `/cmds` remains available, `/acmds` denies level-0 players, and admin levels 1-5 see only commands at or below their level; RCON admins should see every admin level.

## Player state and timers

1. Join a DM while standard players are active, a referee/substitute is present, and a player is dead. Confirm active standard players do not receive the join message, referees/substitutes and non-playing players do, and using `/dm <same ID>` again returns to the DM spawn without another announcement.
2. Die in a DM, then use `/lobby`, `/view`, or `/spec`. Confirm the player does not return to the old DM after a later death or reconnect.
3. Repeat with DM ID `0` in a test database. Death should respawn into that DM, and leaving it should clear the pending DM state.
4. Queue a delayed player action, disconnect, and reconnect another player into the same player slot. Confirm the old callback does not affect the new connection.
5. Run `/rava` with fewer than two eligible players. Confirm it refuses to start. Then start All-vs-All with at least two players and confirm every streamed participant has a visible map marker. Finish gunmenu selection and confirm the weapon-set announcement reaches all active participants without an immediate standalone `/matchtips` message. Confirm `/matchtips` appears as one of the periodic tips for players with tips enabled. Let one player be removed for leaving the arena and confirm the round continues while another participant remains. After All-vs-All ends, start `/rb` and `/ra`; confirm their normal team-based marker visibility is restored and enemy markers stay hidden. Disconnect one player during the start countdown and confirm a round that ends immediately does not open a delayed gunmenu afterward.
6. Start an arena with blackout bounds, end it, then start an arena with invalid/out-of-world bounds on a test copy. Confirm blackout zones are destroyed between rounds and invalid bounds do not leave stale zones.
7. Start exterior and interior arenas. Confirm the start camera begins without a positional jump, moves smoothly through the six-second countdown, and stops when players spawn. Cancel a start during the countdown and confirm the camera timer stops; then start a base and confirm its camera path is unchanged.
8. Connect from an IP whose AKA record contains multiple names, including the first and last entries. Confirm each existing name is recognized and is not appended a second time.
9. Enable Anti-C-bug and Anti-slidebug in `/config`, then restart. Confirm both options persist and apply to players in the lobby, rounds, DMs, and duels. Reproduce the crouch/fire sequence with a supported weapon and verify the C-bug detector freezes the player for two seconds; ordinary firing and crouching without the exploit must remain unaffected. For Anti-slidebug, tap crouch with a 9mm pistol, Deagle, shotgun, AK-47, sniper rifle, minigun, or spray can, then press W or S, left Shift (sprint), and right mouse (aim) together within two seconds; space is jump, not sprint. Confirm the player is frozen without needing to fire; sprinting and aiming without a recent crouch, movement direction, or supported weapon must remain unaffected. Toggle Anti-C-bug with `/anticbug on` and `/anticbug off`; neither command should call `loadfs` or `unloadfs`.
10. Install the ColAndreas plugin in the server's `plugins` directory and its collision database at `scriptfiles/colandreas/ColAndreas.cadb`; `config.json` now loads the plugin. Confirm the server log reports that the map loaded; without that database team pings must be disabled with an explicit error. In an active BASE match and a normal team ARENA, aim with a supported firearm and press the walk key (Alt by default). Confirm attackers see object 19606, defenders see object 19607, and both teams' radar icons use marker type 56; pings are visible only to the sender's team, including substitutes, not enemies or spectators. In third-person weapon aim (camera mode 53), verify the ping endpoint follows the default GTA SA crosshair position (0.53, 0.40) and uses the current camera zoom/FOV; compare Desert Eagle with Cuntgun, M4, and AK-47 against nearby and distant surfaces. Verify pings cannot be created or received outside an active base/team-arena round, including lobby, DM, duel, spectators, and All-vs-All; team arena pings remain enabled. Test a short-range weapon and a sniper rifle: each ping must stop at the first ColAndreas world collision or at that weapon's configured maximum range, whichever comes first. Verify pings are separated by sender, a new ping replaces that sender's prior ping, all pings disappear after five seconds, and disconnecting the sender or a teammate cleans up their per-player objects/icons.
11. In an active team BASE match and team ARENA, have a teammate deal exactly 20 effective damage to an enemy before another teammate kills them. Confirm the damage dealer gets one assist, the killer does not, multiple qualifying teammates each get one, and damage below 20 gives none. Confirm the count resets for the victim's next life; environmental/team kills, All-vs-All, DMs, duels, and out-of-round damage award none. Check `/stats` and the player details dialog, restart using a database copy, and confirm the lifetime assist count persists.
12. Start a BASE and a team ARENA. Confirm chat announces the map number/name, play count and team wins, then lists active attackers and defenders. Select two gunmenu weapons with different teammates and confirm the team sees `has chosen weapon set: Deagle(1) / Rifle(1)`-style messages, where each parenthesized number is the weapon's current selection order/slot count. The old HUD/FPS warning should not appear.
13. During an active exterior team arena, add a new player with `/add`. Confirm the player sees the arena blackout boundary after spawning and the team status HUD immediately includes their configured health and armour; their individual HP bar must also start at the correct value. Repeat in an interior arena without outdoor blackout bounds.
14. In a disposable server, trigger each enabled net warning multiple times with a normal reading between episodes. Confirm low FPS, high FPS, packet-loss, and high-ping counters continue from their previous warning instead of returning to `1/N`; confirm each counter caps at its configured threshold and the matching action occurs once. Reconnect to confirm counters start at zero.
15. Trigger automatic AFK while playing a round. Confirm the player is removed from the round, becomes a referee, spawns in the lobby frozen and invulnerable, and the round-wide AFK message is sent. Trigger automatic AFK outside a round; confirm the player is sent to the lobby frozen and invulnerable without the round-wide message. Manual AFK players must remain invulnerable.
16. Select each available `/style` option and confirm the choice persists after reconnecting; Bulletproof must not appear in the menu, and Simple, Team Status Icons, and Team HP Bars must still select their correct styles. Confirm Modern and Simple share three independent textdraws for Kills, Damage, and Total Dmg at `(3, 396)`, `(3, 405)`, and `(3, 414)`, using white labels and red values. Switch from Team Status Icons to Modern during BASE and team ARENA: the `BaseID_VS` text must no longer retain the AAD formatting. In Team Status Icons only, verify the stats panel appears at the reference position and displays Kills, Dmg, Total, and Ratio in that order, each on a separate line; Kills and Dmg must show round values, Ratio must use the current match's `TotalKills / TotalDeaths` calculation (zero if there are no match deaths), and Total must show match damage. Confirm the match Ratio updates after a kill/death and immediately resets to `0.00` when `/war` ends. In Team HP Bars, verify Damage and Total use separate red textdraws at their exported positions, one line per textdraw; all styles must update both damage values live and retain their own panel design. Confirm the duplicate `BaseID_VS` label is hidden and the HP Bars center text shows the base/arena and timer. During the starting countdown, verify both team names and player counts remain visible while both team HP labels and bar fills show zero; once the round starts, verify the bars and HP labels reflect the new round, not the previous round. Verify both colored fills shrink outward symmetrically over the translucent track. When a team takes damage, its bar should briefly use the specified green (`#083E0D`) or blue (`#08104A`) for about three seconds, then return to its normal color: green `0x1B321BFA`, blue `0x04157687`. Damage to one team must not flash the other team's bar. Confirm death does not shrink the maximum or refill the remaining players' bar. Repeat in BASE and team ARENA, during checkpoint captures, and after a late player joins. In BASE, confirm the team bars remain visible after the `IgnoreSpawn` spawn path. In an active BASE and team ARENA, use `/sethp` and `/setarmour` on a participant and verify every team HP display and their individual team bar updates immediately; use the same commands on a lobby player and confirm they do not change round HUD values. In All-vs-All, confirm the standard HUD remains visible without empty team bars. Confirm `/themes` is no longer registered and the remaining styles retain their existing appearance.

## Paused-player sync regression

1. With two clients on foot in a disposable server, pause the victim with ESC for more than two seconds, then hit them non-lethally with fists. Observers must not see the victim jump to Blueberry or change virtual world/interior; after unpausing, confirm the server and client still agree on the victim's position and health/armour.
2. While the victim remains paused, confirm their visible health/armour bar decreases after each hit. Confirm the brief hit indicator shows the armour model while armour remains and the health model after armour is depleted, then disappears after about one second.
3. Repeat the paused-hit test in a base round, an arena, a DM, and a duel. Also test a round paused by `/rr` with pause mode set to pause the round.
4. Kill a paused player and verify observers still see the normal death/corpse behavior, the death callback runs once, and the player respawns once at the correct spawn. Confirm no stale ESC bubble appears after death.
5. Repeat after spectating, AFK, disconnecting, and reconnecting into the same player slot. Confirm none of those states leaks a paused marker or sync to the new session.
6. Pause a player while they are capturing a base or arena checkpoint. Confirm the ESC label is at the same height as the damage label and hidden behind walls. All active round players should receive one notice naming the player paused in the checkpoint. Confirm the paused player is removed from the capture and the timer resets to the full configured duration; after unpausing, they count again only if still inside the checkpoint.
## Persistence recovery

1. On a disposable database, hold a SQLite write lock while producing a casual score or map-stat update.
2. Release the lock before the retry limit expires. Confirm the log reports recovery and the stored score/statistic is applied exactly once.
3. Keep the lock through all retries. Confirm the final error is explicit and the update remains pending only in memory. Pending updates are not durable across a server restart, so resolve this condition before restarting.

## Round damage panel style isolation

1. Switch between Modern and Simple and confirm they share three independent PlayerTextDraws (`RoundStyleKillsTD`, `RoundStyleDamageTD`, `RoundStyleTotalDmgTD`) for Kills, Damage, and Total Dmg at `(3, 396)`, `(3, 405)`, and `(3, 414)`, using white labels and red values.
2. Switch to Team Status Icons and Team HP Bars and confirm each shows only its own dedicated panel; Team Status Icons must show Kills, Dmg, Total, and Ratio, while Team HP Bars must show separate Damage and Total textdraws. A legacy saved Bulletproof style should use its own panel.
3. Switch styles repeatedly during an active round and after spectating, death camera, and freecam. Confirm no style's panel appears with another style's position, color, text, or formatting.

## Team HP bar roster updates

1. During an active round with Team HP Bars selected, remove the last player from one team and confirm its bar becomes empty. Add a full-health player to that team with `/addme` (or the applicable add command) and confirm the bar immediately fills to 100%.
2. Remove a player from a team with other players remaining, then add a player. Confirm the bar width is recalculated from the current roster and current team HP, not the previous roster's capacity.
3. Confirm the normal bar colors are green `0x1B321BFA` and blue `0x04157687`; damage flashes remain unchanged.
